# Можно ли создать программу генерации инфографики на связке Cline + DeepSeek + VS Code с установщиком для Windows?

## Короткий честный ответ

**Да, это реально, и почти всё решается бесплатными инструментами.** Но сразу три важные поправки, чтобы не было ложных ожиданий:

1. **DeepSeek API не умеет искать и скачивать картинки.** Это текстовая языковая модель. Она отлично работает с текстом (чистка названий, формулировки характеристик, написание SVG-кода), но найти и скачать фотографию товара на белом фоне она не сможет. Для онлайн-режима нужен отдельный сервис поиска изображений (ниже подробно).

2. **Paint не подходит.** Это интерактивная программа, из кода вашего приложения её не запустить и не отдать ей команды. Вместо неё вся графика выполняется внутри самой программы библиотекой **Pillow** — это и есть «встроенный графический движок», бесплатный и полностью автоматический.

3. **Cline и VS Code нужны только на этапе разработки.** В готовую программу они не попадают. Установщик будет содержать только ваше автономное приложение, а DeepSeek API — только в онлайн-режиме, как вы и написали.

## Онлайн-режим — честно про поиск картинок

Повторим главное: **DeepSeek API — текстовая модель, картинки не выдаёт.** Для поиска фотографий товаров по названию нужен один из вариантов:

- **Bing Image Search API** (Microsoft) — есть бесплатный уровень (порядка 1000 запросов в месяц). Надёжный вариант.
- **Google Custom Search JSON API** — 100 бесплатных запросов в день.
- **SerpAPI** и аналоги — удобно, но платно.
- **Парсинг маркетплейсов** (Wildberries, Ozon) — не рекомендую: это нарушает правила сервисов, ломается, есть юридический риск.
- **Openverse** — бесплатный поиск изображений, но готовых «товарных» фото там почти нет.

Как я предлагаю устроить онлайн-режим, чтобы он был рабочим: программа ищет по названию товара N вариантов через API поиска, показывает их пользователю в окошке, пользователь выбирает подходящее фото. Дальше программа автоматически проверяет углы изображения (белые ли они) и при необходимости убирает фон локально через `rembg`. Такой «выбор человеком» резко повышает качество результата.

## Иконки: ваши + генерируемые

- Иконки, которые вы дадите, кладутся в папку `assets/icons` и используются как есть.
- SVG — это обычный текстовый XML. Его можно генерировать кодом, а DeepSeek отлично пишет SVG по описанию.
- Готовый SVG превращается в PNG нужного размера с помощью `cairosvg`.
- Если захотите расширить набор — библиотеки свободных иконок (Material Symbols, Feather, Bootstrap Icons) с открытыми лицензиями.

## Из чего соберётся установщик

1. Python-приложение (интерфейс + Pillow + openpyxl).
2. **PyInstaller** превращает его в один `.exe` (бесплатно, собирается на Windows).
3. **Inno Setup** (или NSIS) делает из exe установщик `setup.exe` — с иконкой, названием и т.д. (бесплатно).
4. В установщик входит только ваше приложение. Cline/VS Code там нет.
5. **DeepSeek API-ключ.** Главный нюанс при продаже: ключ, «зашитый» в exe, можно извлечь. Поэтому честные варианты: (а) каждый клиент вводит свой ключ — просто и безопасно; (б) ваш ключ с шифрованием — удобнее, но не 100% защита; (в) свой небольшой сервер-посредник, который проксирует запросы к DeepSeek, — правильно, если продаёте крупно, но это уже серверная часть.

## Отдельная кнопка: интеграция в Figma

Да, это можно, и это хорошая идея. Готовая карточка — это просто PNG, а Figma вставляет изображения без труда. Есть три уровня интеграции — от простого к полному:

**Уровень 1 — «полу-автоматический» (надёжен всегда, 0 доп. кода со стороны Figma).**
Кнопка «Вставить в Figma»: приложение сохраняет карточки, кладёт активную карточку в буфер обмена (Pillow умеет это на Windows) и открывает Figma. Дальше пользователь жмёт Ctrl+V — карточка в макете. Самый простой и стабильный вариант; подходит, если карточек немного.

**Уровень 2 — свой плагин Figma (настоящая интеграция, рекомендую).**
Плагин — это маленькая бесплатная программа внутри Figma (JS, ~200–400 строк), устанавливается один раз из Figma (приватный плагин). Кнопка в вашем приложении делает три вещи:
1. сохраняет готовые карточки во временную папку;
2. поднимает маленький локальный сервер (localhost), который раздаёт картинки;
3. открывает Figma и запускает плагин.

Плагин через API (`figma.createImageAsync()` / `figma.createImage()` из байтов) вставляет картинки, создаёт фреймы 900×1200 с именами `товар_001…007`, раскладывает их сеткой на странице и выставляет настройки экспорта. Всё это автоматически.

Честный нюанс: плагины работают в «песочнице» и не могут напрямую читать диск Windows. Поэтому картинки передаются одним из способов: локальный сервер (удобно, но localhost+https иногда капризничает), стандартный диалог выбора файлов внутри плагина (работает в 100% случаев — плагин открывает окно «выберите файлы», пользователь выбирает папку с карточками) или буфер обмена. На практике надёжная схема: кнопка в приложении = «сохранить карточки + открыть Figma», а плагин сам спрашивает папку.

**Уровень 3 — Figma REST API (без плагина) — не подходит для этой задачи.**
Через личный токен доступа API умеет создавать новый файл, читать документ, оставлять комментарии, работать с переменными. Но вставлять изображения, фигуры и текст в документ REST API не умеет — это делается только плагинами. Так что сам по себе REST API «наложить карточки в макет» не сможет, только создать пустой файл и открыть его.

**Что это даёт:** карточки можно дорабатывать в Figma (брендинг, шрифты), шарить с клиентом, собирать все товары в один мудборд. Плагин бесплатный и работает даже на бесплатном тарифе Figma. К разработке добавит примерно 2–3 дня.

## Редактируемый формат и редактор карточек («мини-Figma» в приложении)

**Честно про «формат проекта Figma» (.fig).** Файл `.fig` — это закрытый проприетарный формат (внутри ZIP + внутренний JSON), он не задокументирован официально и меняется Figma без предупреждения. Генерировать настоящий редактируемый `.fig` извне — это реверс-инжиниринг: работает ненадёжно и ломается при обновлениях Figma. Официально поддерживаемый «редактируемый» формат, который можно создать вне Figma и импортировать, — **SVG** (текст остаётся текстом, фигуры — векторными узлами). Figma импортирует SVG простым перетаскиванием — без всякого API.

**Поэтому правильная архитектура такая:**

1. **Свой формат проекта (JSON) — «микро-Figma» прямо в приложении.** Набор из 7 карточек = один файл проекта (например, `.mcproj`). Каждая карточка = список слоёв: фон, фото товара, плашки, иконки, тексты, рамка. У каждого слоя — позиция, размер, поворот, цвет, прозрачность, шрифт. Именно этот формат и есть «редактируемый».

2. **Вкладка «Проект карточек»** — отдельная вкладка в приложении:
   - слева — список товаров/комплектов;
   - в центре — окно предпросмотра с **плавным листанием** (кнопки «←» и «→», анимация сдвига; карточки заранее отрисованы в превью-размере — листание мгновенное и плавное даже на слабом ПК);
   - справа — **редактор слоёв**: выделили элемент (текст, иконку, плашку) — меняете текст, шрифт, цвет, размер, положение;
   - кнопки **«Сохранить»** (пишет изменения в файл проекта) и **«Отмена»** (откат текущей сессии правок к последнему сохранению);
   - предпросмотр перерисовывается в реальном времени (превью 360×480 — это быстро).

3. **Экспорт «для Figma»** — кнопка «Экспорт в SVG (для Figma)»: каждая карточка сохраняется как SVG (тексты и фигуры — редактируемые, фото товара — встроенное внутри). В Figma карточку перетаскивают в документ — и всё редактируется. API Figma при этом не используется вообще, что соответствует вашему условию.

4. **Кнопка «Скачать .fig» (реально, но честно о риске).** Файл `.fig` — это ZIP-архив, внутри которого лежат `document.json` (вся структура: слои, компоненты, стили), `thumbnail.png` и папка `images/` с самими картинками. Сообщество частично расшифровало формат, существуют библиотеки (например, npm-пакет `figma-file`), которые умеют собирать такие файлы, — ваша программа сможет сгенерировать `.fig` с сохранением слоёв, компонентов и стилей комплекта из 7 карточек. **Но это реверс-инжиниринг неофициального формата:** файл может перестать открываться после обновления Figma, а сложные элементы (стили текста, компоненты) поддерживаются не полностью. Поэтому кнопка «Скачать .fig» будет, но рядом всегда будет кнопка «Скачать SVG» — официальный и стабильный путь.

5. **Роль DeepSeek (только свой ключ пользователя).** В настройках пользователь вводит свой API-ключ — он хранится локально на компьютере и никуда не передаётся. DeepSeek — текстовая модель, она не рендерит картинки. Но в редакторе она реально полезна:
   - кнопка «Улучшить текст» — переписать/сократить характеристику;
   - «Сгенерировать иконку» — DeepSeek пишет SVG по описанию («иконка стиральной машины, тонкая линия, цвет #2E5BFF»), приложение сразу показывает результат в предпросмотре;
   - «Применить правку» — DeepSeek выдаёт JSON-команду изменений для выделенного слоя («сделать плашку ярче, увеличить кнопку "Купить"»), приложение применяет её как серию изменений;
   - «Подобрать палитру» — цвета под бренд.
   Редактирование остаётся в руках пользователя (двигаете элементы мышью, меняете вручную), DeepSeek автоматизирует текстовые и дизайн-решения.

**Почему так, а не «всё внутри Figma»:** Figma API вы исключили — и он действительно не нужен, а `.fig` надёжно генерировать нельзя. Свой JSON-проект + превью + редактор + SVG-экспорт — это полноценный автономный редактор: открывает и правит карточки без интернета и без Figma, а в Figma уезжает только как готовый редактируемый SVG (по желанию).

**Что потребуется:** графический интерфейс на **PySide6 (Qt)** — он умеет и плавную анимацию листания, и перетаскивание слоёв мышью (Tkinter для этого слабоват). Это заметное изменение стека: бесплатно, установщик станет тяжелее на ~15–25 МБ.

**Сроки:** редактор с вкладкой, листанием, слоями и кнопками Сохранить/Отмена — плюс **4–7 дней** к общей оценке.

## Поле поиска товара и конвертация картинок в PNG

- В режиме «Онлайн» появляется **отдельное текстовое поле поиска**: вводите название товара → программа ищет фото в интернете через API поиска изображений (DeepSeek это не умеет — он текстовая модель, см. раздел «Онлайн-режим») и показывает варианты для выбора.
- Любую найденную картинку (JPG, WebP, TIFF, BMP, GIF и т.д.) программа **сразу конвертирует в PNG** — это делает Pillow, без дополнительных программ.
- Дальше — проверка «белого фона» (анализ углов) и при желании удаление фона нейросетью `rembg`, чтобы товар на карточке выглядел аккуратно.
- Готовый PNG автоматически попадает в проект карточек как слой «Фото товара» и участвует в превью и редакторе как обычно.

## Использование установленных Photoshop / CorelDRAW (локальный режим)

Да, можно — на Windows оба приложения умеют управляться из кода через COM-автоматизацию, без облака, всё локально.

**Photoshop (из двух — рекомендуемый вариант).**
- У Photoshop есть официальный механизм скриптов (ExtendScript/JSX) и COM-интерфейс. Ваша программа на Python вызывает установленный Photoshop: `win32com` → `Photoshop.Application` → выполняет JSX-скрипт (`ps.DoJavaScript(...)`), который открывает файл, делает нужную обработку (кадрирование, коррекция, резкость, сохранение PNG/JPG/PSD).
- «Плагин» — это и есть ваш JSX-скрипт: он лежит рядом с программой, и программа передаёт его в Photoshop. Дополнительно можно вызывать готовые Actions (.atn).
- Честные нюансы: Photoshop должен быть установлен и лицензирован у пользователя; первый запуск Photoshop долгий; при продаже программы нельзя требовать Photoshop у клиента — поэтому модуль делается опциональным.

**CorelDRAW.**
- У CorelDRAW есть COM-автоматизация и VBA-макросы (.GMS). Программа на Python управляет CorelDRAW через COM (`CorelDRAW.Application`) и запускает VBA-макросы. Для растровой обработки фото используется Corel PHOTO-PAINT (входит в комплект).
- Честные нюансы: документация по COM скуднее, чем у Photoshop, и API менее стабилен между версиями.

**Как это встраивается в архитектуру:**
- Это опциональный движок обработки для локального режима: пользователь выбирает в настройках «Pillow (встроенный, работает всегда)», «Photoshop» или «CorelDRAW».
- Программа передаёт в выбранное приложение исходное фото и параметры → приложение обрабатывает → сохраняет результат → программа забирает готовый PNG и продолжает сборку карточки как обычно.
- Встроенный Pillow остаётся «запасным двигателем», который работает всегда и везде.

**Сроки:** модуль интеграции Photoshop/Corel — плюс **3–6 дней**; он не обязателен для первой версии.

## Бесплатная векторная программа, которой можно задавать правила (вместо Photoshop/Corel)

Если не хотите привязываться к платным Photoshop/CorelDRAW — есть бесплатная альтернатива, которая идеально вписывается в схему «задай правила → редактируй → сведи → сохрани»:

**Inkscape (рекомендую) — бесплатный векторный редактор (лицензия GPL, ставится на Windows).**
- Родной формат — SVG, а «сведение» изображения — это сборка слоёв (фото товара, плашки, иконки, тексты), как в нашем формате проекта.
- Задавать правила можно тремя способами:
  1. **Командная строка:** `inkscape --actions="select-all;export-filename:out.png;export-do" file.svg` — Inkscape открывает SVG, выполняет список команд и сохраняет PNG/PDF.
  2. **Python-расширения (inkex):** пишете Python-скрипт-«правило» — он получает документ, меняет слои и атрибуты, возвращает результат. Это и есть «правила редактирования».
  3. Просто использовать Inkscape как рендерер: программа строит SVG (как в плане), Inkscape конвертирует его в PNG/PDF/JPG нужного размера (900×1200).
- Полностью бесплатен, автоматизируется, не требует лицензии у клиентов.

**GIMP — бесплатный растровый редактор (для обработки фото, не вектор).**
- Управляется через Python-Fu (скрипты на Python) и пакетный режим командной строки: открыть → обработать (фон, коррекция, резкость) → сохранить.
- Подходит для этапа подготовки фото перед сборкой карточки.

**ImageMagick — без интерфейса, самый быстрый «движок сведения».**
- Чистый CLI: конвертация, масштабирование, наложение, вырезание фона по цвету, сохранение. Не векторный редактор, а инструмент — часто удобнее всех для пакетной обработки.

**Что выбрать в нашем приложении:** настройка «Движок обработки»: Pillow (встроенный, работает всегда), Inkscape (векторный SVG-конвейер), GIMP или ImageMagick (растровая обработка), Photoshop/CorelDRAW (опционально, если установлены). Inkscape закрывает «векторную» часть бесплатно, GIMP/ImageMagick — растровую.

**Сроки:** интеграция Inkscape — плюс **2–4 дня** к оценке.

## Дополнительные связки инструментов для качественной сборки

На «качество» влияют: аккуратная замена фона (края без ореола), мягкие тени, чёткий текст, единая цветовая гамма. Связки — от простой к максимальной:

**Связка A — «Всё встроено» (рекомендую для первой версии, ноль установок).**
Pillow (композиция: фото, плашки, текст, тени) + rembg (замена фона нейросетью, работает на компьютере). Текст — Pillow с качественными шрифтами с кириллицей (Inter, Manrope, Rubik). Плюс **суперсэмплинг**: рендер в 2× (1800×2400) и уменьшение до 900×1200 — края и буквы получаются чёткими.

**Связка B — «Максимум качества, свободный софт».**
- Замена фона: rembg или **BiRefNet** (ещё аккуратнее края: волоски, блики); для товаров на чисто белом фоне — мгновенный и точный flood-fill (заливка белого) через Pillow/OpenCV.
- Композиция: Pillow + **OpenCV** — мягкие тени под товаром, сглаживание краёв (feather), наложение с учётом прозрачности.
- Текст: **WeasyPrint** — рисует карточку по HTML/CSS, как в браузере: автоперенос, межбуквенные интервалы, тени, градиенты. Уровень типографики дизайнера.
- Вектор-рендер по желанию: Inkscape.

**Связка C — «Управляем внешними редакторами».**
GIMP (Python-Fu), Inkscape (inkex), Photoshop/CorelDRAW (COM) — как движки, которым приложение отдаёт правила и забирает результат. Актуально, если редакторы уже стоят у пользователя.

**Связка D — «Максимально точная вырезка» (если есть GPU или не жалко времени).**
Segment Anything (SAM2) + rembg: самые точные маски, идеальная замена фона даже на сложных фото.

**Совет по качеству (бесплатно и сразу):** суперсэмплинг 2×, мягкая тень под товаром, единая цветовая схема плашек, один фирменный шрифт. Это даёт 90% «дорогого» вида без платного софта.

## Связка D — на чём это работает (железо)

- **Компоненты:** PyTorch + модели SAM2 (tiny/small/base/large) + rembg. Модели скачиваются при первом запуске, дальше работают офлайн. Windows 10/11 x64.
- **Минимум (только CPU):** 4 ядра (i5/Ryzen 5), 16 ГБ RAM, ~5 ГБ на диске. SAM2 tiny — 1–3 минуты на фото, rembg — 1–3 секунды на фото.
- **Комфортно (NVIDIA GPU + CUDA):** видеокарта RTX 2060 и выше, 6+ ГБ VRAM — SAM2 tiny справляется за 1–5 секунд на фото.
- **Оперативная память:** 8 ГБ достаточно для rembg; для SAM2 желательно 16 ГБ.
- **Размер программы:** PyTorch с CUDA — это ~3–5 ГБ дополнительно. Поэтому в базовую версию Связку D не встраиваем: это опциональный модуль, который ставится по требованию, сам определяет GPU и подключает нужную модель.
- **Рекомендация:** по умолчанию — rembg (работает на любом ПК); модуль SAM2 автоматически включается, только если программа обнаружила видеокарту NVIDIA.

## Стоимость связки и отдельные кнопки-движки

**Стоимость инструментов — практически 0 ₽.** Всё в списке — свободное ПО с разрешением коммерческого использования: Pillow, openpyxl, PySide6, PyInstaller, Inno Setup, rembg, Inkscape, GIMP, ImageMagick, WeasyPrint, OpenCV, SAM2 (Apache 2.0). Модели SAM2/rembg скачиваются бесплатно.

Опциональные платные элементы:
- Поиск картинок онлайн: Bing Image Search — бесплатный лимит ~1000 запросов/мес, Google Custom Search — 100/день; сверх лимитов — небольшая оплата.
- DeepSeek API — оплата за токены по своему ключу (суммы небольшие).
- Photoshop/CorelDRAW — если пользователь хочет этот движок, софт покупает он (PS — подписка, Corel — разовая покупка). Сама интеграция бесплатна.
- Figma — бесплатный тариф достаточен (API не используем).

**Отдельные кнопки-движки в приложении** (каждый — самостоятельный модуль, выбирается пользователем):
- «Сборка: Pillow» — встроенный, работает всегда (базовый).
- «Inkscape» — векторный рендер SVG→PNG/PDF; кнопка активна, если установлен Inkscape (бесплатно).
- «Photoshop / CorelDRAW» — модуль для установленных редакторов (через скрипты/COM); если программы нет — кнопка сообщает об этом.
- «Вырезка фона: rembg» — нейросеть, работает на любом ПК (базовый).
- «Вырезка фона: SAM2» — максимальное качество маски, отдельная кнопка; модуль ставится по требованию (+3–5 ГБ), ускоряется на NVIDIA GPU.

**Что такое SAM2:** Segment Anything Model 2 — нейросеть от Meta для выделения объектов на фото (открытая, Apache 2.0, работает локально). Понимает «что на фото главное» и вырезает объект с точной маской даже на сложном фоне (шерсть, волосы, прозрачные предметы). По сравнению с rembg края заметно точнее, но требуется больше ресурсов (PyTorch, желателен GPU).

**Сроки разработки модулей:** Inkscape +2–4 дня, PS/Corel +3–6 дней, SAM2 +3–5 дней.

## Отдельный блок «Инфографика по образцу» (шаблон)

Да, можно — это фактически «конструктор шаблонов»: один образец превращается в многоразовый шаблон, под который подставляются фото и тексты любых товаров.

**Честно о сложности:** автоматически превратить произвольный растровый образец в идеальные векторные слои с распознанным текстом — ненадёжно (это задача уровня «распознать дизайн», требует ИИ и всё равно ошибается). Поэтому делаем надёжный гибрид:

1. **Загрузка образца** — пользователь выбирает картинку-образец (из файла или из интернета — то же поле поиска).
2. **Авто-разбор образца** (программа делает сама):
   - извлекает **палитру** (главные цвета плашек, фона, текста);
   - находит **зоны**: область фото товара (самый крупный однородный/центральный прямоугольник, находится через контуры OpenCV), цветные плашки, рамки, границы текстовых блоков.
3. **Векторные слои по образцу** — найденные зоны превращаются в слои нашего проекта (прямоугольники-плашки, рамки, текстовые поля, иконки) — это и есть «векторный слой по образцу». Текст берётся не из картинки, а из Excel (это надёжнее распознавания).
4. **Доработка в редакторе** — пользователь поправляет зоны мышью (вкладка «Проект карточек» уже умеет) и **сохраняет шаблон**.
5. **Массовое применение** — к шаблону подставляются фото товаров (из папки или из онлайн-поиска) и характеристики из Excel; каждая карточка собирается и сохраняется 900×1200 (PNG/JPG/PDF).

**Итог:** один образец → готовый шаблон → сколько угодно товаров одной кнопкой. Блок добавляется к проекту, сроки: **+3–6 дней**.

## Честные ограничения и риски

- **Онлайн-режим — самый хрупкий блок:** зависимость от сторонних API, лимиты, изменение их политик. Запасной вариант — режим «Из папки», он всегда работает.
- **Фото товаров — чужие изображения.** Для карточек, которые продаются, важно прояснить права на фото (свои съёмки или лицензии). Аналогично с иконками.
- **900×1200** — пропорция 3:4, в целом подходит для современных требований WB/Ozon; стоит свериться с актуальными требованиями площадки перед тиражом.
- **Качество поиска онлайн** зависит от названий товаров: неточные названия → неточные фото. Выбор пользователя это смягчает.
- **Большие партии товаров** — обработку надо делать пакетами/очередью, чтобы программа не «подвисала».
