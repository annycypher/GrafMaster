# План разработки: генератор инфографики для маркетплейсов

> К этому плану мы будем обращаться по мере работы. Каждый этап пронумерован, в конце каждого — критерий проверки.

## Общая архитектура

```
Приложение (Python + PySide6)
├─ Вкладка «Главная»          — режимы «Из папки»/«Онлайн», запуск сборки
├─ Вкладка «Проект карточек»  — мини-Figma: листание, редактор слоёв, Сохранить/Отмена
├─ Вкладка «Шаблоны»          — конструктор «по образцу»
├─ Вкладка «Настройки»        — ключ DeepSeek, движки, палитра, шрифты
│
├─ Слой данных
│   ├─ Чтение Excel (openpyxl) → товары и характеристики
│   └─ Модель товара / карточки
├─ Слой ресурсов
│   ├─ Поиск фото «Из папки» (диалог Windows)
│   ├─ Поиск фото «Онлайн» (API поиска изображений)
│   ├─ Конвертация в PNG (Pillow)
│   └─ Движки замены фона: flood-fill / rembg / SAM2 (опц.)
├─ Слой проекта
│   ├─ Формат проекта .mcproj (JSON): слои, стили, палитра
│   ├─ Рендер: Pillow (+ опц. Inkscape / WeasyPrint)
│   ├─ Редактор слоёв и предпросмотр (Qt)
│   └─ Экспорт: PNG / JPG / PDF / SVG / .fig (эксперим.)
└─ Слой ИИ (DeepSeek, ключ пользователя)
    ├─ Улучшение текстов, генерация иконок (SVG)
    ├─ JSON-команды правок, палитры
    └─ Онлайн-режим: уточнение запросов поиска
```

## Ключевые решения
1. Свой формат проекта `.mcproj` (JSON) — главный «редактируемый» формат.
2. SVG — официальный путь импорта в Figma; `.fig` — экспериментальный (ZIP: document.json + images/).
3. Pillow — базовый движок; Inkscape / PS / Corel / SAM2 — опциональные модули-кнопки.
4. Все ИИ-запросы — только по ключу пользователя (хранится локально).
5. Карточки 900×1200, рендер с суперсэмплингом 2×.

## Этапы

### Этап 0. Подготовка и согласование (0.5–1 день)
1. Согласовать структуру Excel-файла (название, характеристики, фото).
2. Собрать 2–3 фото товаров на белом фоне.
3. Собрать иконки, рамки/плашки (если есть).
4. Получить образец готовой карточки «как должно выглядеть».
5. Установить Python 3.11+, PySide6, Pillow, openpyxl.
6. Получить и проверить DeepSeek API-ключ.
- Результат: входные материалы + окружение.
- Проверка: программа открывает пустое окно.

### Этап 1. Каркас приложения (1–2 дня)
1. Окно с вкладками: Главная, Проект карточек, Шаблоны, Настройки.
2. Главная: переключатель «Из папки» / «Онлайн».
3. Диалог выбора папки с материалами.
4. Настройки: поле API-ключа DeepSeek (сохраняется локально).
5. Базовые кнопки: Скачать JPG / PDF / SVG / .fig.
- Проверка: вкладки открываются, ключ сохраняется после перезапуска.

### Этап 2. Чтение Excel (1–2 дня)
1. openpyxl: чтение товаров и характеристик.
2. Сопоставление колонок: название, фото, характеристики.
3. Обработка ошибок: пустые ячейки, листы, кодировки.
4. Таблица товаров в интерфейсе.
- Проверка: 10 строк Excel читаются без ошибок.

### Этап 3. Режим «Из папки» (2–3 дня)
1. Выбор папки, сопоставление фото с товарами по имени.
2. Проверка «белого фона» (анализ углов и гистограммы).
3. Замена фона flood-fill для товаров на белом.
4. Автомасштаб и центрирование фото в области карточки.
5. Отчёт: найдено/не найдено фото по каждому товару.
- Проверка: 7 из 10 товаров автоматически получили корректное фото.

### Этап 4. Сборка карточки на Pillow (3–5 дней)
1. Холст 900×1200, суперсэмплинг 2× (1800×2400 → 900×1200).
2. Шаблон карточки: плашка, рамка, фото, текст, иконки.
3. Характеристики по 1–2 на карточку из Excel.
4. Кириллические шрифты (Inter, Manrope, Rubik).
5. 7 макетов на товар, имена товар_001…007.
6. Кнопки «Скачать JPG», «Скачать PDF» (многостраничный).
- Проверка: для товара созданы 7 карточек 900×1200.

### Этап 5. Проект и редактор «мини-Figma» (4–7 дней)
1. Формат `.mcproj` (JSON): слои, стили, палитра.
2. Вкладка «Проект карточек»: список комплектов слева.
3. Предпросмотр с плавным листанием (кнопки ← →).
4. Редактор слоёв: текст, шрифт, цвет, размер, положение.
5. Кнопки «Сохранить» / «Отмена» (откат к последнему сохранению).
6. Перерисовка предпросмотра в реальном времени.
- Проверка: правка текста видна сразу; «Отмена» возвращает состояние.

### Этап 6. Экспорт SVG и .fig (2–4 дня)
1. Экспорт карточки в SVG (тексты и фигуры редактируемые).
2. Экспериментальный экспорт .fig (ZIP: document.json + thumbnail + images/).
3. Кнопка «Вставить в Figma»: буфер обмена + открытие Figma.
4. (Опц.) Плагин Figma: локальный сервер + автосетка фреймов.
- Проверка: SVG открывается в Figma и редактируется; .fig открывается в текущей версии.

### Этап 7. Онлайн-режим (3–5 дней)
1. Поле поиска по названию товара.
2. API поиска изображений (Bing/Google), список вариантов.
3. Окно выбора фото пользователем.
4. Скачивание + конвертация в PNG.
5. Проверка белого фона / rembg при необходимости.
- Проверка: для 8 из 10 товаров найдено подходящее фото.

### Этап 8. DeepSeek-интеграция (2–4 дня)
1. Клиент API DeepSeek с ключом из настроек.
2. «Улучшить текст» — переписать/сократить характеристику.
3. «Сгенерировать иконку» — SVG по описанию, сразу в предпросмотр.
4. «Применить правку» — JSON-команда изменения слоя.
5. «Подобрать палитру» — цвета под бренд.
6. Обработка ошибок: таймауты, нет сети, неверный ключ.
- Проверка: все 4 функции работают с ключом пользователя.

### Этап 9. Шаблоны «по образцу» (3–6 дней)
1. Загрузка образца (файл/интернет).
2. Авто-разбор: палитра + зоны (OpenCV: фото, плашки, тексты).
3. Превращение зон в слои проекта.
4. Доработка в редакторе, сохранение шаблона.
5. Массовое применение к товарам (фото + Excel).
- Проверка: шаблон применяется к 10 товарам без ручных правок.

### Этап 10. Движки обработки (опционально, по отдельности)
10.1. Inkscape (2–4 дня): рендер SVG→PNG/PDF, кнопка-модуль.
10.2. GIMP / ImageMagick (2–3 дня): пакетная обработка фото.
10.3. Photoshop / CorelDRAW (3–6 дней): скрипты/COM, отдельная кнопка.
10.4. SAM2 (3–5 дней): максимальная точность маски, автоопределение GPU.
10.5. Панель выбора движка в настройках.
- Проверка: выбранный движок обрабатывает фото и возвращает PNG.

### Этап 11. Качество (2–3 дня)
1. Суперсэмплинг 2× везде.
2. Мягкая тень под товаром, сглаживание краёв.
3. WeasyPrint: типографика (переносы, интервалы, тени).
4. Единая палитра и фирменный шрифт из настроек.
- Проверка: карточки визуально соответствуют образцу.

### Этап 12. Установщик (2–4 дня)
1. PyInstaller → единый .exe.
2. Inno Setup → setup.exe (иконка, имя, каталог установки).
3. Тест на чистой Windows (без Python).
4. Опциональные модули (SAM2/PyTorch) — отдельным установщиком.
- Проверка: установка и работа на чистой машине.

### Этап 13. Тестирование и приёмка (2–3 дня)
1. Сквозной тест: Excel → фото (папка) → 7 карточек → JPG/PDF.
2. Сквозной тест: онлайн-поиск → PNG → сборка.
3. Редактор: правки, Сохранить/Отмена, листание.
4. Экспорты: PNG/JPG/PDF/SVG/.fig.
5. Чек-лист лицензий (шрифты, иконки, фото, модели ИИ).
- Проверка: все сценарии проходят без ошибок.

### Этап 14. Продажа и передача (1–2 дня)
1. Документация пользователя.
2. Решение по ключу DeepSeek (встроенный/клиентский/прокси).
3. Демо-видео и образцы карточек.
- Проверка: клиент сам устанавливает и собирает карточки.

## Сводка по срокам
- **Базовая версия** (этапы 0–8 + 11–13): ≈ **25–30 рабочих дней**.
## Хранение проекта и GitHub

- **Где живёт проект:** в папке разработки, например `GrafMaster\` на диске (реальный код). Макеты и документы уже лежат в `infografika-plan\`.
- **GitHub — да, можно и нужно.** Код (Python) занимает единицы мегабайт — это не «тяжело». На GitHub бесплатны и публичные, и приватные репозитории.
- **Что НЕ кладём в репозиторий** (через `.gitignore`):
  - модели нейросетей (rembg/SAM2 — 0.2–2.5 ГБ) — скачиваются при первом запуске;
  - PyTorch/CUDA и установщики (.exe/.msi) — для них есть раздел «Releases»;
  - собранные карточки и кэш — выходные файлы;
  - папки `.venv`, `__pycache__`, файлы с API-ключами.
- **Что помещается:** исходники, иконки, шрифты, примеры, документация — до ~50 МБ.
- **Правила GitHub:** лимит ~100 МБ на файл; для крупных бинарников — Git LFS (нам не нужно).
- **Установщики** (50–150 МБ) выкладываем в раздел **Releases** — их можно скачивать/передавать/продавать.
- **Итог:** проект легко живёт на GitHub; тяжёлое (модели, exe, фото) — вне git: модели скачиваются при установке, установщики — в Releases.
